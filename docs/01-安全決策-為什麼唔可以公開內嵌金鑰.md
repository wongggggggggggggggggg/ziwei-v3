# 01 · 安全決策：為什麼「把 API 放進去」唔可以直接公開

> 你嘅要求：「i want to put the api inside, but with a safe version, after done, i will put it online to public」
> 呢份文件就係回答「有冇一個安全嘅內嵌做法」。答案係：**冇**。以下係事實與替代方案。

---

## 1. 一句話結論

> **靜態網頁內嵌 API 金鑰 ＝ 公開金鑰。**
> 你可以「加密／混淆」，但**任何**瀏覽器睇得到嘅嘢，訪客都拆得開。
> 真正安全只有兩條路：① 金鑰留在伺服器（Worker 代理）；② 每個使用者自備金鑰。

---

## 2. 為什麼（可驗證事實，唔係推論）

| 事實 | 你可以自己驗證 |
|------|----------------|
| HTML 係純文字檔 | 右鍵「檢視網頁原始碼」／ Ctrl+U |
| 執行中的 JS 一樣睇得到 | F12 → Sources → 頁面內 inline script |
| 網絡請求 header 一樣睇得到 | F12 → Network → 任何一次請求 → Request Headers |
| localStorage 一樣睇得到 | F12 → Application → Local Storage |
| 爬蟲會主動掃 | GitHub Secret Scanning、公開 repo 掃描 bot（金鑰可能被自動撤銷） |

**所以：** 你把金鑰寫進 `CONFIG.INLINE_API_KEY`，放上 GitHub Pages，等於把金鑰貼在門口。
唯一分別係「要撳 F12」還是「要 decodes 一段 base64」—— 兩者都係 10 秒內的事。

### 2.1 那些「保護手法」實際上保護到幾多？

| 手法 | 阻擋 casual user | 阻擋稍懂技術的人 | 阻擋掃描 bot |
|------|------------------|------------------|--------------|
| Base64 編碼 | 少少 | ❌ 完全冇 | ❌ |
| 字串拆開拼接（`"sk-" + "abc"`） | 少少 | ❌ | ❌ |
| XOR／AES + 前端解密 | 少少 | ❌（key 也在前端） | ❌ |
| 只在登入後才注入 | 有 | ❌ | ❌ |
| **Worker 代理（金鑰在伺服器）** | ✅ | ✅ | ✅ |
| **使用者自備金鑰** | ✅ | ✅ | ✅ |

> 一句：**前端加密＝把鎖匙同鎖一齊寄出去。**

---

## 3. v2 提供嘅三種模式（自動判斷優先次序）

| 模式 | 設定方法 | 金鑰在哪 | 可否公開 | 適用 |
|------|----------|----------|----------|------|
| **proxy**（推薦公開用） | `CONFIG.PROXY_URL` = 你嘅 Worker 網址 | Cloudflare Worker 環境變數（加密 secret） | ✅ **安全** | 公開網站、分享給朋友 |
| **inline**（只限私人） | `CONFIG.INLINE_API_KEY` = 你的金鑰 | 檔案內明文 | ❌ **等於公開** | 只在自己電腦開（file:// / localhost） |
| **manual**（預設） | 使用者在設定頁貼上 | 瀏覽器 sessionStorage／localStorage | ✅ **安全** | 唔想搞伺服器，但又想公開 |

### 3.1 v2 已加入嘅保護措施（就算你揀 inline 都有）

1. **公開網址自動示警**：如果偵測到「已內嵌金鑰 + 唔係 file:// 或 localhost」，頁面頂部會出現紅色警示條，講明「任何訪客都可以取走金鑰」。
2. **CSP 限制連線目的地**：`connect-src` 只准 `api.deepseek.com` 同 `*.workers.dev`（自訂網域由腳本自動加）。即係就算有人注入 script，都好難把金鑰送去第三方。
3. **金鑰遮罩顯示**：設定頁只顯示 `sk-a…wxyz`，唔會顯示完整金鑰。
4. **預設不記住**：唔勾「記住金鑰」＝只存 sessionStorage，關閉分頁即失效。
5. **移除硬編碼位**：v2 已刪除原版那個「隨手填金鑰」嘅 `DEEPSEEK_API_KEY` 常數（原版最大地雷）。

---

## 4. 你應該點做（建議）

### 情況 A：想公開，又要用「你嘅金鑰」（推薦）
1. 部署 `02-改進版\worker\ziwei-proxy-worker.js` 到 Cloudflare Workers（免費，5 分鐘，見 `04-部署指引.md`）。
2. 金鑰只放 Worker 的 secret（`DEEPSEEK_API_KEY`），永遠唔會送到瀏覽器。
3. 雙擊 `01-指令\Build-Public-Proxy.cmd`，貼上 Worker 網址 → 產生 `public\ziwei-ai-v2-public-<時間>.html`。
4. 把**呢個 public 檔**上載到 GitHub Pages。它**完全冇金鑰**。

### 情況 B：只想自己用（唔想搞伺服器）
1. 雙擊 `01-指令\Build-Private.cmd`，貼上金鑰 → 產生 `private\ziwei-ai-v2-private-<時間>.html`。
2. **只在自己電腦開**。唔好上載、唔好 commit、唔好放雲端硬碟公開連結。
3. 若 `file://` 開唔到（CORS `origin: null`），用 `01-指令\Serve-Local.cmd` 開 `http://localhost:8080`。

### 情況 C：公開，但唔想管金鑰
用預設 `manual` 模式：訪客自己貼自己的 DeepSeek 金鑰（原版就係咁）。零成本、零風險，但訪客要有 DeepSeek 帳號。

---

## 5. 如果金鑰真係洩漏了

1. 立即去 <https://platform.deepseek.com/api_keys> **撤銷（delete）**該金鑰。
2. 建立新金鑰。
3. 檢查用量／帳單有無異常。
4. 如果係 GitHub，記得清除 commit 歷史（唔止刪檔）—— 或者直接視為已洩漏。
