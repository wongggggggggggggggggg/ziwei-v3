# 09 · 追問功能與主題限制（v3）

> 版本：前端 v3.0.0｜Worker v3.6（同一個 Worker，兩站共用）
> 更新：2026-11-15

---

## 一、追問是什麼

解讀完成後，結果下方會出現「**追問**」區：

```
┌ 追問 ─────────────────────────────┐
│ 只回答你問嘅問題，唔會重寫上面嘅解讀 │
│ ⚠️ 只限紫微斗數／牌卡相關問題        │
│ [ 想追問什麼？              ]  →    │
│ 你問：…                            │
│ 答：…（串流逐字）                    │
└────────────────────────────────────┘
```

- 每次追問會**帶上完整原解讀 + 牌組**，所以答案**一定對得上原文**
- 答案**串流逐字**顯示，唔需要等全文
- 追問會存落「解讀歷史」，載入舊紀錄時一併還原

## 二、寫入系統提示詞的規則（R14–R17）

| # | 規則 | 內容 |
|---|---|---|
| R14 | **只答問題** | 不重寫、不摘要、不重複原本七段解讀 |
| R15 | **沿用原牌組與結論** | 必須用原本主星／輔星／長生；與原解讀矛盾時先指出差異 |
| R16 | **長度按難度** | 簡單 1–3 句；中等 1–2 段；複雜可分點；**全文上限 3000 中文字** |
| R17 | **拒答程式／數學／功課** | 不出程式碼、不出算式；用一兩句說明並把話題帶回牌組 |
| R18 | **原文不壓縮** | 送給 AI 的原解讀上限 30,000 字元（超過才截斷，並標註），確保意思不被改動 |

### prompt 原文（節錄）
```
7. 用繁體中文（台灣用語），語氣溫暖、務實、可執行。
8. 如果使用者問的是程式碼／編程／除錯／演算法／數學計算／解方程／功課解題，
   不要解答、不要給出程式碼或算式；用一兩句說明「本服務只做紫微斗數牌卡解讀，
   不處理程式或數學問題」，然後把話題帶回牌組象徵與他現實的處境。
9. 每次回答最多 3000 個中文字；問題簡單就簡短，不要為了長而長。
```

## 三、兩層攔截（前端 + AI）

| 層 | 做法 | 例子 |
|---|---|---|
| 前端 | `BLOCKED_TOPIC_PATTERNS`：英文關鍵字（python/js/sql/regex/api/bug…）＋中文（程式/代碼/編程/微積分/方程/證明題…）＋簡單算式 | 打「幫我寫 python」→ 直接提示唔支援，**唔會花你 token** |
| AI | prompt R17 | 就算繞過前端（例如問得很隱晦），AI 都會拒答並帶回話題 |

> 好處：明顯的程式／數學題**在送出前就被擋**，省錢又快。

## 四、限制一覽（可改）

| 常數（在 `index.html` 的 CONFIG） | 值 | 意思 |
|---|---|---|
| `FOLLOWUP_MAX_CHARS` | **3000** | 追問答案的上限（中文字） |
| `FOLLOWUP_CONTEXT_MAX` | **30000** | 送給 AI 的原解讀上限（字元） |
| `FOLLOWUP_BLOCK_TOPICS` | **true** | 是否啟用程式／數學攔截 |

> ⚠️ **關於「30000 字」**：DeepSeek 單次回覆受 `max_tokens` 限制（本專案設 4000），
> 實際最多約 3000–4000 中文字。想要 30000 字回覆＝要 `max_tokens` 提升到 ~30000，
> 成本會變成 10 倍以上，而且手機閱讀體驗差。**本專案採用 3000 字上限 + 30000 字元 context 上限**。

---

## 五、額度

- 每次追問 = 1 次 `/chat` = **扣 1 次額度**（個人每週 10 次、全站 40 次）
- 追問太多會用完額度 → 用解鎖碼 `tccs`（+10 個人／+40 全站）

## 六、程式位置

| 功能 | 檔案／函式 |

| UI | `index.html` → `#followupBox` |

| 串流 | 重用 `readStream()` |
